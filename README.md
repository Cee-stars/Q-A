# 質問応答ドリル

毎日8分の英語スピーキング・ドリルを進行する PWA。

チェックリスト項目名: **質問応答（復習→3回回答→添削→定着）**

| 工程 | 時間 | 中身 |
|------|------|------|
| 1 準備 | 0秒 | 前夜に先読み（Phase 2） |
| 2 復習 | 80秒 | 過去の添削文を4枚。思い出して言う → 答えを見て読む |
| 3 3回回答 | 45+35+25秒 | **同じ1問**を時間を縮めて3回（4/3/2） |
| 4 添削 | 120秒 | 3回目の答えを書き直す |
| 5 定着 | 60秒 | 読む → 見ずに言う → 読む |

合計 **6分5秒**。残りは遅延の吸収に使い、工程は増やさない。

**なぜこの形なのか**は [docs/PLAN.md](docs/PLAN.md) の第2章に根拠を書いてある。
時間配分を変えるときは先にそこを読むこと。

## 開発

```sh
npm install
npm run dev        # http://localhost:5173
npm run build      # 型チェック + ビルド
npm test           # 配色・ロジック・ブラウザ通し・API配線
```

`npm run test:api` は Claude API を差し替えて添削と先読み生成の配線を確かめる。
実際に課金される呼び出しはしない。

`npm run test:smoke` は時計を偽装して6分15秒のセッションを一気に通し、
工程の遷移と記録の保存を確認する。スクリーンショットは `test/shots/` に出る。

## APIキー

設定画面で入力する。**この端末の IndexedDB にだけ保存され**、リポジトリにも配信物にも入らない。
キーが空でも、種問題バンク60問で練習そのものは成立する。

誰かに配る・端末を共有する段になったら、薄いプロキシ越しに差し替えること
（`src/claude.ts` の1ファイルで閉じている）。

## 公開

`main` への push で GitHub Pages に配信される（`.github/workflows/deploy.yml`）。
リポジトリの Settings → Pages で Source を **GitHub Actions** にしておくこと。
マイクと Wake Lock は HTTPS でしか動かないため、Pages 配信が前提。

## 既知の制約（Phase 1）

- セッション中にリロードすると、その回は最初からになる（記録は残る）。
- 到達工程の記録は端末内の IndexedDB のみ。端末間で同期しない。
