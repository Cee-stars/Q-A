# 質問応答ドリル

毎日8分の英語スピーキング・ドリルを進行する PWA。

チェックリスト項目名: **質問応答（Q10音読→3問回答→1問添削）**

| 工程 | 時間 |
|------|------|
| 1 生成 | 0秒（Phase 2 で前夜に先読み） |
| 2 Q10音読 | 60秒 |
| 3 3問回答 | 45秒 × 3 |
| 4 1問添削 | 120秒 |
| 5 3回音読 | 60秒 |

合計 **6分15秒**。残りは遅延の吸収に使い、工程は増やさない。
設計の意図と今後のフェーズは [docs/PLAN.md](docs/PLAN.md) を参照。

## 開発

```sh
npm install
npm run dev        # http://localhost:5173
npm run build      # 型チェック + ビルド
npm test           # ロジック検証 + ブラウザ通し検証
```

`npm run test:smoke` は時計を偽装して6分15秒のセッションを一気に通し、
工程の遷移と記録の保存を確認する。スクリーンショットは `test/shots/` に出る。

## 公開

`main` への push で GitHub Pages に配信される（`.github/workflows/deploy.yml`）。
リポジトリの Settings → Pages で Source を **GitHub Actions** にしておくこと。
マイクと Wake Lock は HTTPS でしか動かないため、Pages 配信が前提。

## 既知の制約（Phase 1）

- セッション中にリロードすると、その回は最初からになる（記録は残る）。
- 到達工程の記録は端末内の IndexedDB のみ。端末間で同期しない。
