# 英語即答トレーニングアプリ PRD

2026-10-12 時点のスナップショット。編集・コメントできる版は共有ドキュメント側にあり、そちらが最新。

沈黙の原因を英語力ではなく「準備時間ゼロ」と「型の不在」に置き、10秒準備＋発話、PREP の型、クッションフレーズの反射、無音の可視化の4機能で構成する筋トレ型アプリ。

## 1. プロダクト概要とコンセプト

**「"I don't know what to say" を、1秒で終わらせる。」**

オンライン英会話で質問されてから話し始めるまでの時間を短くするアプリ。新しい英語を教えるのではなく、すでに知っている英語を出す速度を上げる。1日8〜10分、毎日。

### ターゲット

| 項目 | 内容 |
| --- | --- |
| レベル | 初級〜中級（CEFR A2〜B1、TOEIC 400〜700 目安） |
| 状況 | オンライン英会話を週1〜3回受講中。質問されると固まる |
| 症状 | 日本語で答えを考えてから英訳しようとして間に合わない。沈黙が怖くて焦り、さらに出なくなる |
| 持っているもの | 中学〜高校文法の知識と基本語彙。読めば分かる |
| 持っていないもの | 答えの出し方の型、沈黙を埋める定型句、とりあえず話し始める習慣 |

### 沈黙が起きる3つの原因と、担当する機能

沈黙は1つの原因ではなく、3つが直列につながって起きる。機能はそれぞれに1対1で対応させる。

| 原因 | 何が起きているか | 担当機能 |
| --- | --- | --- |
| 思考言語の切替 | 日本語で内容を考え、英訳しようとする。変換の負荷が発話開始を遅らせる | 10秒準備（英語の単語だけでメモを取らせる） |
| 型の不在 | 何から言うか決まっていないので、文全体を組み立て終わるまで話せない | PREP ビルディング |
| 沈黙への焦り | 間が空くほど焦り、ワーキングメモリが焦りに食われて、さらに出なくなる | 1秒即答クッションフレーズ＋無音の可視化 |

### 設計原則

1. **口が先、正しさは後** — 発話中は止めない。言い換えや修正はセッション後にまとめて見る
2. **10秒は「考える時間」ではなく「型に流し込む時間」** — 内容を練らせると日本語思考に戻る。結論1語と理由1語を置くだけにする
3. **沈黙を数字にする** — 主観の「詰まった感じ」ではなく、初語までの秒数と無音の割合で進捗を見る
4. **上げるのは速度だけ** — 語彙と表現の仕入れは本アプリの外。ここで伸びるのはアクセス速度であって、語彙量ではない

### やらないこと

- 文法の体系的な学習、単語帳、発音矯正
- 発音スコアの判定（沈黙の原因ではなく、改善にも時間がかかる）
- AI との自由会話（別ジャンル。本アプリは1人で短時間、毎日やる筋トレ）
- 録音音声の共有・公開機能

## 2. 成功指標

北極星指標は「発話モード開始から最初の発声までの時間（TTFW）の週次中央値」。ユーザーの痛み（沈黙）そのものであり、マイクの音量だけで測れるので Phase 1 から計測でき、練習で動く。

| 指標 | 定義 | 計測元 | 仮の目標値 |
| --- | --- | --- | --- |
| TTFW（北極星） | 発話モード開始から最初の発声までの秒数、週次中央値 | 端末内の音量検出 | 4週で 6秒 → 2秒 |
| 無音率 | 発話時間に対する1.5秒以上の無音の合計の割合 | 端末内の音量検出 | 8週で 40% → 20% |
| 最長無音 | 1回の発話中の最も長い無音の秒数 | 端末内の音量検出 | 8秒 → 3秒 |
| 完走率 | 目標秒数まで止めずに話せた回の割合 | セッション記録 | 70% 以上 |
| 反射成功率 | 1秒即答ゲームで目標内に発声できた割合 | 端末内の音量検出 | 80% 以上 |
| 7日継続率 | 初回利用から7日後にまだセッションを完了している割合 | セッション記録 | 40% 以上 |
| レッスン自己申告 | 「今週のレッスンで固まった回数」を週1回1タップで入力 | 週次プロンプト | 減少傾向 |

最後の1行が唯一の外部妥当指標。アプリ内の数字が良くなってもレッスンで固まる回数が減らなければ、練習の転移が起きていない。減らないときに疑うのは、お題が実際のレッスンで聞かれる質問から離れている可能性。

### 見張る指標（悪化を許さない）

- 1セッションの所要時間：中央値で 10分 を超えない
- 発話中の中止率：発話モードを途中で止めた回の割合が 20% を超えない（超えたら目標秒数が長すぎる）

## 3. 仕様の数字の検証

指示された4機能のうち、3つの数字はそのままだと初級〜中級には成立しない。機能自体は残し、数字を段階化することを推奨する。

| 仕様の数字 | 読み | 推奨 |
| --- | --- | --- |
| 60秒話す | 準備なしで60秒話せるなら、その人は最初から固まっていない。既存の類似ツールをこのターゲット層に当てたとき、「手本なしで答える」工程で実際に2日連続で手が止まった | 目標秒数を 20 → 30 → 45 → 60 秒と段階化。同じお題で目標に届いたら次の秒数に上がる |
| 1秒でクッション | **これは正しく、最も効く機能**。新しい文を組み立てるにはおよそ 600〜1500ms かかるので、冷えた状態から1秒で新規の文は無理。しかしクッションフレーズは「作る」のでなく「記憶済みの塊を取り出す」ので、1秒に入る | Phase 1 に置く。ただし固定の1秒ゲートは初日にほぼ全失敗するので、本人の初回中央値から始めて段階的に下げる適応ゲートにする |
| PREP 4要素 | 10秒で4スロットなら1スロット 2.5秒。Point を作るだけで計画に1秒前後かかるので、使い切る | Point + Reason の2スロットで開始。安定したら Example を追加。最後の Point は定型句（So that's why I think so.）で代用し、話し終わりの合図にする |

### あとから後悔しないための前提

- **このアプリでは語彙は増えない。** 出力練習は「すでに言えることを速くする」もので、言えないことは待っても出てこない。お題と一緒に「言い方」を先に渡す画面を入れる
- **発話中に訂正を出さない。** 訂正フィードバックは「即時かつ明示的」が短期に最も効くが、それは「話し終わった直後」のこと。発話中の割り込みは沈黙を増やす
- **同じ日の繰り返しだけでは残らない。** 集中練習は当日の再生は良いが忘却が速い。同じお題を 1 / 3 / 7 / 21 日後に再出題する
- **音読とシャドーイングの成果は、統制された課題での測定が多い。** 実際の会話への転移は自動ではないので、外部妥当指標（レッスン自己申告）を最初から入れておく

上記の秒数は本プロジェクトで先に調べた発話計画・練習効果の研究（発話計画の所要時間、会話のターン間ギャップ 100〜300ms、定型表現が自然発話の 50〜80% を占めるとする推定、練習の冪乗則、訂正フィードバックのメタ分析）に基づく**概数**で、ここでは出典URLを持っていない。数字を外に出すときは原典に当たること。

| S1 | ホーム | 今日のメニューと連続記録。入口は3つ | 5秒 |

## 5. ワイヤーフレーム：S1 ホーム

ホームの仕事は1つ。**迷わず1タップで発話まで行かせること**。お題の選択はここではさせない（選択は迷いを生み、迷いは隣のアプリに負ける）。

```
┌──────────────────────────────┐
  即答トレーニング             [⚙]
└──────────────────────────────┘

  7日連続   ● ● ● ● ● ● ●

 ──────────────────────────────
  今日のドリル
  目標 30秒 × 5問
  残り 3問（前日の持ち越し 1問）

        [     始める     ]
 ──────────────────────────────
  1秒即答ゲーム
  前回の中央値 1.4秒 → 次の目標 1.2秒

        [  90秒だけやる  ]
 ──────────────────────────────
  今週の数字
  初語まで    4.1秒    ▼ 0.8
  無音率       34%    ▼ 5pt
  完走率       60%    ▲ 10pt
 ──────────────────────────────

  お題ライブラリ                 ›
  履歴・推移                     ›
```

| 要素 | 仕様 |
| --- | --- |
| 「始める」 | 1タップで S3。お題は選択中のプレイリストから自動に出題。マイク許可が未取得ならこのタップで要求する（iOS はユーザー操作中でないと通らない） |
| 残り問数 | 今日の未完了数。前日に目標秒数に届かなかったお題を先頭に繰り越す |
| 連続記録 | 「週3日以上で維持」。毎日を強制すると1日落とした時点で離脱する |
| 今週の数字 | 3つまで。北極星指標（初語まで）を一番上。前週比の矢印は改善方向を緑、悪化をグレーで表示し、赤は使わない |
| 1秒即答ゲーム | 時間がない日の逃げ道。「90秒だけ」と明記して、ゼロの日を作らない |
| 在席通知 | 1日1回、ユーザーが指定した時刻。本文はお題そのものを表示し、ロック画面で考え始められるようにする |

## 6. ワイヤーフレーム：S3 思考モード / S4 発話モード

思考モードで10秒のうちに文字を打たせるのは成立しない。スマホで英文を打つだけで10秒が溶ける。そこで**練習モードを2つに分ける**。

| モード | 準備 | PREPスロット | 使いどころ |
| --- | --- | --- | --- |
| ビルド | 時間無制限 | 書き込む（英語の単語だけ） | 初めてのお題、最初の1週 |
| クイック | 10秒 | ラベル表示のみ、頭の中で埋める | 2週目以降の日常 |

同じお題は「ビルドで一度書いてから話す」→「翌日以降はクイックですぐ話す」の順に出題する。内容を一度自分で作っておくことが、繰り返しで速くなる前提条件。

### S3 思考モード（クイック）

```
┌──────────────────────────────┐
  ‹ 戻る                     3 / 5
└──────────────────────────────┘

  Q. What did you do last weekend?
     先週末は何をしましたか？

 ──────────────────────────────
       のこり   7 秒
       ▬▬▬▬▬▬▬▬▬▬▬▭▭▭▭
 ──────────────────────────────

  日本語で文を作らない。英語の単語を
  2つだけ頭に置く。

  P  結論   ── I ...
  R  理由   ── Because ...

        [   言い方を見る   ]

        [   もう話せる   ]
```

### S4 発話モード

```
┌──────────────────────────────┐
                             3 / 5
└──────────────────────────────┘

  What did you do last weekend?

 ──────────────────────────────
     0:18        目標 0:30

     ▁▃▅▇▅▃▁▁▁▁▁▃▅▇▇▅▃▁
                 └─ 無音 2.4秒
 ──────────────────────────────
  P  結論        ● 言えた
  R  理由        ○
 ──────────────────────────────

  詰まったらこれを言う
  Let me see...    /    Well, ...

        [     ストップ     ]
```

| 要素 | 仕様 |
| --- | --- |
| タイマー | カウントアップ。目標を超えても止めず、ストップまで計る。目標到達は音なしの振動と表示色で知らせる |
| 波形 | リアルタイムの音量。録音が生きていることの証。無音区間をその場で色分けする |
| クッションの提示 | 無音が 1.5秒 を超えた瞬間に画面下に出す。沈黙への焦りを直接手当てする唯一の仕組み |
| PREP チェック | Phase 1・2 は本人のタップ（言えたら押す）。Phase 3 で文字起こしから自動判定に差し替える |
| 自動終了 | 無音 20秒 で停止。パニックして放置したセッションを永久に残さない |
| 画面 | 発話中はスリープを抑止。Web で作る場合、iOS はバックグラウンド往復で解除されるので visibilitychange で再取得が必要 |
| 戻る | 出さない。誤タップで録音が消える事故を防ぐ |
| オープニング | 発話モードに入った 0.3秒後に短い音。「いまから」を耳で渡し、画面を見ずに済むようにする |

## 7. ワイヤーフレーム：S6 AIフィードバック結果

この画面の原則は**点数をつけない**こと。点数は焦りを生む。出すのは秒数と前回比だけ。

```
┌──────────────────────────────┐
  ‹ 終わる                3 / 5
└──────────────────────────────┘

  What did you do last weekend?

 ──────────────────────────────
  話した時間   34秒 / 目標 30秒  到達
  初語まで     2.1秒   前回 3.4秒
  無音         合計 11秒（32%）
               最長 4.2秒
 ──────────────────────────────
  沈黙の場所

  0s       10       20       30
  ████░░░█████░░░░█████████
      ↑ 4.2秒    ↑ 3.1秒
      ここで止まった
 ──────────────────────────────
  話した内容

  I went hiking with my friend.
  (4.2s) Um... the weather was
  very good so we... (3.1s) we
  walked about three hours.
 ──────────────────────────────
  短く言える形に

  1  the weather was very good so
     → it was nice, so
  2  walked about three hours
     → walked for three hours

          [  3回音読する  ]
 ──────────────────────────────
  P 結論 ●      R 理由 ●

     [ 同じお題でもう1回 ]
     [     次のお題     ]
```

| ブロック | 何から作るか | 登場 |
| --- | --- | --- |
| 秒数・無音・沈黙の帯 | 端末内の音量解析のみ。通信とAPIは不要 | Phase 1 |
| 話した内容 | 音声認識。無音は転写に (秒) として差し込む | Phase 2 |
| 短く言える形に | LLM。最大3件、「短く・簡単に」方向のみ | Phase 3 |

### この画面で決めたこと

- **文法の網羅的な添削はしない。** 直す点が多すぎて読まれない。出すのは「もっと短く言う形」だけ。このターゲット層の課題は正確さではなく速度
- **語数が増える提案は機械的に捨てる。** LLM の出力をそのまま出さず、元の表現より長い提案はコードで除外する
- **最長無音の直前の語を指す。** 「ここで止まった」は次に覚えるべき表現の場所。ここから語彙の仕入れにつなげる
- **訂正は発話直後に出す。** 即時かつ明示的な訂正が短期に最も効く。ただし「発話中」ではなく「発話後」
- **3回音読は定着用。** 同じ話を秒数を減らして繰り返す練習（4/3/2）とは別物で、混ぜない。後者は「同じお題でもう1回」側

## 8. ワイヤーフレーム：S8 1秒即答ゲーム

8問で 90秒。四機能の中で唯一、成果がその日のうちに数字で返ってくるので、最初に出す。

### 出題中

```
┌──────────────────────────────┐
  ‹ やめる                   4 / 8
└──────────────────────────────┘

       質問が来たら、
       まず これ を言う

 ──────────────────────────────

    Why do you think so?

          ● 聞いています

 ──────────────────────────────
  このうちのどれでもいい

  Let me see...
  That's a good question.
  Well, how can I say...
```

### 判定（0.8秒だけ表示して次へ）

```
          0.9 秒

   前回 1.4秒  →  今回 0.9秒
```

### S8r 結果

```
┌──────────────────────────────┐
  1秒即答ゲーム   結果
└──────────────────────────────┘

  中央値   1.1秒     前回 1.4秒
  成功     6 / 8     目標 1.2秒以内

  1   0.8   ●
  2   1.0   ●
  3   2.6   ○  間が空いた
  4   0.9   ●
  5   1.1   ●
  6   ─     ○  出なかった
  7   1.0   ●
  8   1.2   ●

  次回の目標   1.0秒

        [ もう1セットやる ]
        [     終わる      ]
```

| 要素 | 仕様 |
| --- | --- |
| 目標秒数 | 固定の1秒ではなく適応ゲート。オンボーディングで測った中央値から始め、達成したセットごとに 0.1秒 下げる。下限 0.8秒 |
| 計測の起点 | お題の描画が完了した瞬間（次のフレームの先頭）。タイマを先に回すとユーザーが見る前の時間を足してしまう |
| 発声の検出 | 端末内の音量。音が「立ち上がった時刻」を返す。確定した時刻を返すと全体が遅く記録される |
| 誤検出対策 | 開始前に 1秒 のノイズフロア較正をし、しきい値を相対で決める。150ms 未満の反応と、持続しない単発音（タップ、机を叩く音）は捨てる |
| 読み上げ | 任意。耳から入れる練習にはなるが、スピーカー音がマイクに回り込んで誤検出する。オンにするならイヤホン案内と、読み上げ終了から 200ms のガードを入れる |
| フレーズ数 | 5〜8 個の小さい固定セットから始める。塊として覚えさせるのが目的なので、多いと塊にならない |
| ミスの扱い | 6秒無反応で次へ。ミスは中央値の計算から除外し、成功率にのみ反映する |

## 9. データ設計

原本は端末内。クラウドは同期のための写しで、なくてもアプリは成立する。

| エンティティ | 主なフィールド | 置き場 |
| --- | --- | --- |
| playlist | id, name, order, updated_at | 端末＋同期 |
| prompt | id, playlist_id, en, ja, model_answer, prep_hint, difficulty, source（seed / user / generated） | 端末＋同期 |
| cushion_phrase | id, text, ja, active | 端末＋同期 |
| session | id, started_at, ended_at, kind（drill / reflex） | 端末＋同期 |
| attempt | id, session_id, prompt_id, mode（build / quick）, target_ms, spoke_ms, **ttfw_ms**, silence_total_ms, silence_max_ms, completed, used_help | 端末＋同期 |
| silence_segment | attempt_id, start_ms, end_ms | 端末のみ |
| transcript | attempt_id, text, words[]（word, start_ms, end_ms）, engine | 端末＋同期 |
| paraphrase | attempt_id, original, suggestion, reason, accepted | 端末＋同期 |
| reflex_attempt | id, session_id, phrase_id, latency_ms, status（hit / slow / miss / suspicious）, target_ms | 端末＋同期 |
| progress | prompt_id, best_ms, attempts, last_at, mastered_at | 端末＋同期 |
| review | prompt_id, stage（0〜3）, due_on | 端末＋同期 |
| recording | attempt_id, file_path, bytes, expires_on | 端末のみ |
| weekly_checkin | week, freeze_count | 端末＋同期 |

中核は attempt。1行に1回の発話。この行だけで全指標が出る。

```sql
CREATE TABLE attempt (
  id               TEXT PRIMARY KEY,
  session_id       TEXT NOT NULL,
  prompt_id        TEXT NOT NULL,
  mode             TEXT NOT NULL,  -- build | quick
  target_ms        INTEGER NOT NULL,
  spoke_ms         INTEGER NOT NULL,
  ttfw_ms          INTEGER,        -- 北極星指標
  silence_total_ms INTEGER NOT NULL,
  silence_max_ms   INTEGER NOT NULL,
  completed        INTEGER NOT NULL,
  used_help        INTEGER NOT NULL,
  created_at       TEXT NOT NULL
);

-- 無音率 = silence_total_ms / spoke_ms
-- 完走    = spoke_ms >= target_ms
-- 出題順  = best_ms が小さい順（苦手なものが先）
```

### 保存と削除の方針

- 音声は**端末内のみ**。既定 7日 で自動削除。最大1分の AAC 64kbps なら1本約 0.5MB、週 35本 で 20MB 前後
- 文字起こしのために音声を外に出すのは**その瞬間だけ**。サーバに残さない
- API キーは端末に置かない。LLM 呼び出しはサーバレス関数経由
- 設定に「全データ削除」を置く。自分の声を扱うアプリでこれがないと使う気にならない

### 同期のマージ規則

端末が2台ある場合、タイムスタンプで上書きすると進捗が巻き戻る。進捗は常に前にしか進めない。

| データ | マージ |
| --- | --- |
| progress | best_ms は小さい方、attempts は大きい方 |
| review | stage が進んでいる方 |
| playlist / prompt | updated_at が新しい方 |
| attempt / reflex_attempt | id で和集合。消さない |

## 10. 必要な AI 機能

AI を 3層に分ける。**下の層は上の層に依存しない**。上の層が落ちても画面は成立する。

| 層 | 何をするか | 通信 | コスト |
| --- | --- | --- | --- |
| 1. 端末内音声解析 | 無音検出、発声開始検出、秒数集計 | 不要 | 0 |
| 2. 音声認識 | 文字起こし＋単語ごとの時刻 | 端末内なら不要 | 0 〜 従量 |
| 3. LLM フィードバック | 言い換え提案、PREP の充足判定 | 必要 | 従量 |

### 層 1：端末内音声解析（「音声解析」は API でなくここ）

仕様書の「無音時間の可視化」は AI API を使わずに全部できる。音量（RMS）を読むだけ。

- **フレーム** 50ms。これより短いと子音の間を無音と誤る
- **しきい値** 固定値でなく、開始前 1秒 のノイズフロアに対する相対値。環境音が部屋で違う
- **無音の定義** しきい値未満が 1.5秒 以上続いた区間。それ未満は普通の語間休止
- **発声開始** しきい値超過が 120ms 続いたら確定。ただし記録するのは**超過が始まった時刻**。確定時刻を使うと TTFW が一様に 120ms 遅くなる
- **マイク設定** echoCancellation オン、noiseSuppression オン、**autoGainControl はオフ**。オートゲインは無音を持ち上げてしきい値を壊す

### 層 2：音声認識

要件は3つ。単語ごとの時刻が返ること（無音を転写に差し込むため）、日本語話者なまりに耐えること、60秒 連続を扱えること。

| 選択肢 | 単語時刻 | コスト | 評価 |
| --- | --- | --- | --- |
| iOS Speech / Android SpeechRecognizer | 返る | 0 | 第一候補。オフラインでも動く。iOS は1回の認識が 1分 制限なので 60秒 は境界。チャンクする |
| Web Speech API | 実装依存 | 0 | iOS Safari で不安定。PWA を選んでもこれに負わせない |
| クラウド STT | 返る | 1分で数円 | 精度が足りないときの逃げ道。切替えられるように抽象化を1枚入れておく |

### 層 3：LLM フィードバック

モデルは `claude-opus-5-5` を既定。量が増えたら `claude-haiku-5-5` に落として比べる。言い換えは難しい課題でないので effort は low から始める。

```ts
// Supabase Edge Function 側。API キーは端末に出さない。
// パッケージのバージョンは実装時に固定する。
import Anthropic from "npm:@anthropic-ai/sdk";
import { zodOutputFormat } from "npm:@anthropic-ai/sdk/helpers/zod";
import { z } from "npm:zod";

const Feedback = z.object({
  paraphrases: z
    .array(
      z.object({
        original: z.string(),
        suggestion: z.string(),
        why: z.string(),
      }),
    )
    .max(3),
  prep: z.object({ point: z.boolean(), reason: z.boolean() }),
  stuck_at: z.string().nullable(),
});

const res = await new Anthropic().messages.parse({
  model: "claude-opus-5-5",
  max_tokens: 2000,
  output_config: {
    effort: "low",
    format: zodOutputFormat(Feedback, "feedback"),
  },
  system: INSTRUCTIONS, // 固定文
  messages: [{ role: "user", content: JSON.stringify(payload) }],
});
```

渡す `payload` はお題、文字起こし、無音の位置、本人のレベル。返った JSON はそのまま画面に出さず、**決定論的フィルタを通す**。

1. 提案が元の表現より語数が多いものを捨てる（「短く」が目的なので例外なし）
2. 元文にない語が 3語 以上増えているものを捨てる（知らない表現を渡されても言えない）
3. 残ったものから先頭 3件。ゼロ件なら言い換えブロックを出さない

### フィードバックの流れ

```
録音終了
 │
 ├─ 層1：端末内集計（必ず実行・オフライン可）
 │    spoke_ms / ttfw_ms / silence[] / 完走
 │    → ここまでで S6 の上半分が描ける
 │
 ├─ 層2：文字起こし（設定でON）
 │    words[] に無音を (秒) として差し込む
 │    失敗 → 上半分だけ出して終わる
 │
 └─ 層3：言い換え（設定でON、層2成功時のみ）
      LLM → JSON → フィルタ → 最大3件
      失敗 → 上半分と文字起こしを出して終わる
```

### コスト見積り（言い換え、ユーザー1人あたり）

1回の入力約 600 トークン、出力約 300 トークン、1日5問、月 150回として試算すると、Opus で月 1.3ドル前後、Haiku に落とすと月 0.03ドル前後。入力が小さいのでプロンプトキャッシュの最小サイズに届かず、キャッシュは効かない。個人利用なら Opus で始めてよく、配布するなら Haiku との比較を先にする。

## 11. MVP 開発ステップ

順序の理由は2つ。1秒即答ゲームを最初に出すのは、四機能の中で唯一**その日のうちに数字が返る**から。言い換え（LLM）を最後にするのは、無音の可視化が API なしで作れるので**お金と認証とサーバを後ろに倒せる**から。

| Phase | 期間 | 入れる | 検証する仮説 | 次へ進む条件 |
| --- | --- | --- | --- | --- |
| 1. 沈黙を数える | 2〜3週 | S0 / S1 / S3クイック / S4 / S6の上半分 / S8・S8r、シードお題30問（日本語訳と手本付き）、端末内音声解析、端末保存 | 反射時間は2週間で下がる。10秒準備＋20〜30秒発話なら毎日続けられる。無音秒数は本人に意味のあるフィードバックになる | 14日中10日実行でき、TTFW 中央値が下がる。下がらなければお題か秒数の設計が違う |
| 2. 言葉を見る | 3〜4週 | 端末内音声認識、S6 全体、ビルドモード、お題ライブラリ（追加・移動）、間隔反復 1/3/7/21日、S9 履歴、読み上げ | 自分の発話を文字で見ると無音の原因が特定できる。ビルド→クイックの順で出題すると完走率が上がる | 無音率が下がり、文字起こしを読んで意味がわかる精度になっている |
| 3. 短くする | 3〜4週 | LLM 言い換え（サーバ経由）、PREP 自動判定、クラウド同期、週次チェックイン | 言い換え提案は次回の発話に実際に現れる | 同じお題の2回目で提案語が使われた率が 30% 以上。下回るなら提案が難しすぎるか多すぎる |

### 入れないと決めたもの（Phase 3 まで）

- 発音評価、AIとの自由会話、ソーシャル要素、ランキング
- アカウント登録（Phase 3 の同期まで不要。登録を先に置くと初日に落ちる）
- 汎用のお題生成（シード 30問 を使い切ってから考える）

### Phase 1 のお題をつくるときの条件

シードお題は**実際のオンラインレッスンで聞かれる質問だけ**にする。教材的な質問（技術の将来、環境問題）を入れると、答えられないのは即答力でなく知識の問題になり、計測が汚れる。3種類に限る。

1. アイスブレイク（How are you? / How was your weekend?）
2. 掘り下げ質問への反射（Why do you think so? / Can you give me an example?）
3. 自分の日常（仕事、住んでいる場所、週末、好きなもの）

## 12. 推奨技術スタック

結論は2段。**Phase 1 の検証はすでに動いている PWA の上でやる。Phase 2 で端末内音声認識と通知が必要になった時点で Flutter に移る**。検証していない仕様のために先に書き直すのは順序が逆。

### ノーコードは使えない

このアプリの核は「ミリ秒単位の音量監視と時刻計測」。録音をファイルに落とすだけならノーコードでもできるが、**発声が始まった時刻が取れない**。それが取れなければ 1秒即答ゲームと無音の可視化が両方消える。残るのは録音アプリ。

| 選択肢 | 音量フレーム | 発声時刻の計測 | 端末内音声認識 | 通知 | 評価 |
| --- | --- | --- | --- | --- | --- |
| Flutter | 取れる | 取れる | 使える | 使える | 推奨。Phase 2 から |
| React Native | 取れる | 取れる | 使える | 使える | Flutter の次。既存知識が TS ならこちら |
| PWA（Web） | 取れる | 取れる | iOS で不安定 | iOS はホーム追加必須 | Phase 1 の検証に最適 |
| ノーコード | 取れない | 取れない | ─ | 使える | 不可 |

### Phase 2 以降の推奨構成

| 層 | 選択 | 理由 |
| --- | --- | --- |
| アプリ | Flutter | 1コードで iOS / Android。音声のプラグインが揃っている |
| 録音と音量 | `record` ＋ 自前の RMS 計算 | プラグインの差し替えに備えて、測定ロジックは自分で持つ |
| 音声認識 | `speech_to_text`（端末内） | 無料、オフライン。クラウドに切り替えられる interface を1枚かぶせる |
| 読み上げ | `flutter_tts` | お題の読み上げ。オンにするならイヤホン案内とガード時間が必要 |
| 画面を消さない | `wakelock_plus` | 発話中のスリープ抑止 |
| ローカルDB | Drift（SQLite） | 推移の集計を SQL で書ける。中央値や週次集計が楽 |
| グラフ | `fl_chart` | S9 の推移 |
| 認証・同期・サーバ | Supabase（Auth / Postgres / Edge Functions） | Phase 3 で初登場。Edge Function は TypeScript なので Anthropic SDK がそのまま使える |
| LLM | Anthropic API（Edge Function 経由） | キーを端末に置かないための唯一の理由 |
| 配布 | TestFlight / 内部テスト | まず自分1人。公開は Phase 3 の後 |

### 個人開発でつまずくところ

- **iOS の端末内音声認識は1リクエスト約 1分 の制限。** 60秒 の目標はちょうど境界にあたる。上限を 45秒 にするか、分割してつなぐ
- **マイク許可はユーザー操作の中でしか要求できない。** ホームの「始める」タップに紐づける
- **スピーカー音の回り込みは実機でしか出ない。** シミュレータで通ったことを信用しない
- **音声プラグインはバージョンで壊れやすい。** 録音と音量取得を自前の薄い層で包んでおく
- **PWA で続ける場合の iOS Safari の制約。** 音声合成は最初の発話をユーザー操作の中で起こす必要があり、終了イベントが来ないことがあるのでタイムアウトを添える。画面点灯の維持はバックグラウンド往復で解除されるので再取得が必要
